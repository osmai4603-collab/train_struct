# معايير السجلات المهيكلة لدورة حياة الخادم (Structured Logging Standards)

السجلات هي المرآة التشغيلية المباشرة لحالة خادم Go. تتبنى هذه المهارة معايير `log/slog` الرسمية مع عمارة إخراج متعددة الأهداف تجمع بين راحة المطور أثناء التطوير المحلي والالتزام بالمعايير الصارمة لبيئات الإنتاج.

## نمط السجلات متعدد الأهداف (Multi-Target Logging)

يتم اكتشاف نوع المخرج (Terminal vs File/Pipe) تلقائياً لتوفير أفضل تجربة:

### 1. وضع الطرفية المطور (Terminal Mode)

- **التنسيق**: نصي سهل القراءة للبشر (Human-readable).
- **الألوان**: استخدام أكواد ANSI عالية التباين لتلوين مستويات السجل (أخضر للمعلومات، أصفر للتحذيرات، أحمر للأخطاء).
- **الوقت**: تنسيق واضح يشمل التاريخ والوقت مع مؤشر `AM/PM` (مثال: `2026-09-14 05:07:07 AM`).

### 2. الحفظ في ملفات مهيكلة (Persistent JSON Mode)

- **التنسيق**: سطور JSON مهيكلة (Newline-delimited JSON).
- **ملف التطبيق العام (`logs/app.log`)**: يسجل جميع أحداث الخادم التشغيلية.
- **ملف الأخطاء المنفصل (`logs/error.log`)**: يفلتر ويضاعف السجلات ذات المستوى `WARN` و `ERROR` لسرعة التحقيق والمراجعة.
- **البيانات**: يجب أن تشمل كل رسالة: `time`, `level`, `msg`, ومفاتيح السياق مثل `server_role`, `addr`, `duration`.

## تقليل الضجيج لفحوصات الصحة (Probe Log Suppression)

في البيئات السحابية ومجموعات Kubernetes، تُرسل فحوصات الصحة الدورية (`/livez`, `/readyz`) كل بضع ثوانٍ، مما يؤدي إلى تضخم هائل وغير مجدٍ للسجلات:

- **القاعدة**: يتم حجب (Suppress) تسجيل الطلبات الناجحة (`Status < 400`) لنقاط فحوصات الصحة لمنع إغراق السجلات.
- **الاستثناء**: إذا فشل فحص الصحة (`Status >= 400`)، يجب تسجيله فوراً بمستوى `WARN` أو `ERROR` لتنبيه الفريق إلى تعطل الخدمة أو انقطاع قاعدة البيانات.

## تفريغ السجلات عند الإغلاق (Log Flush on Teardown)

في المرحلة الأخيرة من دورة حياة الخادم، يجب استدعاء `Sync()` لمقابض الملفات للتأكد من كتابة كافة السجلات المخزنة مؤقتاً في الذاكرة إلى القرص الصلب قبل خروج العملية.
