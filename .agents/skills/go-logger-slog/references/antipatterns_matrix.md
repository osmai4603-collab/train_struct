# مصفوفة الأنماط المضادة وتصحيحها (Anti-Patterns Reference Matrix)

توثق هذه المصفوفة أشهر الأخطاء والممارسات الخاطئة الشائعة في تسجيل الأحداث داخل مشاريع Go، مع توضيح العواقب السلبية والحل المعياري البديل.

---

| # | النمط المضاد (Anti-Pattern) | لماذا يُعد سيئاً؟ (Consequence) | الحل المعياري (Idiomatic Solution) |
| :--- | :--- | :--- | :--- |
| **1** | **التسجيل داخل المكتبات العامة**<br>`log.Printf(...)`<br>داخل حزمة فرعية/مكتبة | يُسلب المستدعي التحكم في مخرجاته، ويجبر التطبيقات المستهلكة على تلقي سجلات مزعجة دون خيار تصفيتها. | **أرجع الخطأ للمستدعي (`return err`)** واترك قرار التسجيل للتطبيق النهائي في الطبقة العليا. |
| **2** | **التسجيل والإرجاع معاً (Log and Return)**<br>`log.Error(err); return err` | يؤدي إلى تكرار نفس الخطأ في كل طبقة برمجية يمر بها، مما يسبب تضخماً وتشويشاً في لوحات المراقبة. | **مبدأ "سجّل أو أرجع"**: إما أن تعالج وتسجل الخطأ، أو تغلّفه (`%w`) وترجعه ليسجله الـ Top Layer handler فقط. |
| **3** | **الاعتماد على السجل العام**<br>`slog.Default().Info(...)` | يخفي التبعيات، ويصعّب كتابة اختبارات الوحدة، ويمنع تخصيص نطاقات فرعية للمكونات والخدمات. | **الحقن الصريح (Explicit DI)** لـ `*slog.Logger` في دالة البناء مع استخدام `.With("component", ...)`. |
| **4** | **إغراق الحلقات الضيقة بالسجلات**<br>`for item := range list { logger.Info(...) }` | اختناق شديد في عمليات الـ I/O، وضغط هائل على الـ GC، واستهلاك باهظ لمساحات تخزين السجلات. | **التسجيل التجميعي (Aggregated Logging)**: سجل بداية الدفعة، والأخطاء الفردية الاستثنائية، وملخصاً عند النهاية. |
| **5** | **تسجيل الحسابات المكلفة دون تحقق**<br>`logger.Debug("dump", expensiveCalc())` | يتم استدعاء الدالة وحساب قيمتها على المعالج حتى لو كان مستوى `DEBUG` معطلاً تماماً في الإنتاج. | **استخدم فحص الجاهزية**: `if logger.Enabled(ctx, slog.LevelDebug) { ... }`. |
| **6** | **تخصيص الذاكرة العشوائي في المسارات الساخنة**<br>`logger.Info("pkt", "id", id, "sz", sz)` | تمرير `any` يسبب Heap Allocations وBoxing، مما يخفض من أداء الخوادم عالية الكثافة. | **استخدم `slog.LogAttrs`** مع الأنواع الصريحة (`slog.String`, `slog.Int`) لتحقيق أداء Zero-Allocation. |
| **7** | **خلط السجلات بالمقاييس (Logs as Metrics)**<br>`logger.Info("request_count", "n", 1)` | السجلات مخصصة للأحداث التفصيلية والتشخيص، وليست لعد الأرقام وحساب المتوسطات الزمنية. | **استخدم أنظمة المقاييس المخصصة** مثل Prometheus Counters / Gauges للسلاسل الزمنية. |
| **8** | **تسجيل البيانات الحساسة كنصوص واضحة**<br>`logger.Info("login", "pass", pass)` | خرق أمني جسيم وقوانين الخصوصية (GDPR/PCI-DSS) عند تخزين الأسرار ورموز JWT في منصات السجلات. | **استخدم واجهة `slog.LogValuer`** أو الحاوية `Sensitive[T]` لإخفاء القيمة آلياً بصيغة `***`. |
| **9** | **تنسيق السجلات يدوياً بالسلاسل النصية**<br>`logger.Info(fmt.Sprintf("user %d done", id))` | يُفقد السجلات قيمتها الهيكلية ويصعّب الفهرسة والفلترة على منصات مثل Datadog وElasticsearch. | **استخدم Structured Key-Value Attrs**: `logger.Info("user done", slog.Int("user_id", id))`. |
| **10** | **إسقاط السياق (Dropping Context)**<br>استخدام `logger.Info` بدلاً من `logger.InfoContext` | ضياع معرفات الطلب والـ Trace IDs ومنع ربط السجل بدورة حياة الطلب عند حدوث مهلات أو إلغاء. | **استخدم دوال `*Context` دائماً** وتمرير `ctx` كأول معامل في استدعاءات السجلات. |
