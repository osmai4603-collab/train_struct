# قائمة مراجعة الجاهزية للإنتاج (`Production Readiness Checklist`)

تحدد هذه القائمة البنود الإلزامية التي يجب استيفاؤها لضمان متانة وموثوقية منظومة الاختبارات وضمان الجودة في مشاريع Go قبل النشر في بيئات الإنتاج الحساسة:

---

## 1. موثوقية التنفيذ والتزامن (Reliability & Concurrency)

- [ ] **كاشف السباق مفعل إلزامياً في الـ CI:** تشغيل الفحص الكامل بـ `go test -race -count=1 ./...` قبل دمج أي فرع.
- [ ] **خلو الحزم من تسريب الـ Goroutines:** فحص الخدمات الخلفية وعمال المعالجة باستخدام `uber-go/goleak` عبر `goleak.VerifyTestMain`.
- [ ] **حظر استخدام `time.Sleep` للمزامنة:** استبدالها بقنوات، أو `sync.WaitGroup`، أو `testing/synctest` في Go 1.24+.
- [ ] **استخدام `t.Parallel()` بأمان:** تفعيل الموازاة للاختبارات المستقلة مع التأكد من عدم مشاركة أي حالة أو متغيرات عامة دون قفل.

---

## 2. نظافة الكود وهندسة الموارد (Resource Lifecycle & Cleanliness)

- [ ] **تنظيف الموارد عبر `t.Cleanup`:** استبدال كافة عبارات `defer` داخل دوال `t.Run` بالدالة المدمجة `t.Cleanup()`.
- [ ] **توثيق دوال المساعدة:** التأكد من وضع `t.Helper()` في السطر الأول من كل دالة مساعدة مشتركة.
- [ ] **استخدام سياق الاختبار في Go 1.24+:** اعتماد `t.Context()` بدلاً من `context.Background()` في الاختبارات التي تطلق اتصالات خارجية.
- [ ] **حماية البيئة والمجلدات:** استخدام `t.Setenv()` لتعديل متغيرات البيئة و `t.TempDir()` أو `t.Chdir()` للملفات المؤقتة.

---

## 3. جودة الفحوصات والتحقق (Assertions & Diagnostic Quality)

- [ ] **التوافق مع قاعدة "Got before Want":** صياغة رسائل الأخطاء بصيغة `Func(args) = got, want want`.
- [ ] **استخدام `google/go-cmp` للمقارنات المعقدة:** فحص الهياكل المتداخلة باستخدام `cmp.Diff` مع ضبط `cmpopts.IgnoreFields` لتجاهل الحقول العشوائية.
- [ ] **الالتزام بضوابط `testify` (إن وُجدت):** حصر `require` بالشروط المسبقة الحتمية واستخدام `assert` للمقارنات مع نصوص توضيحية.

---

## 4. اختبارات التكامل والبيئات الحقيقية (Integration Testing)

- [ ] **عزل اختبارات التكامل بوسم البناء:** وضع `//go:build integration` في السطر الأول لملفات التكامل الثقيلة.
- [ ] **استخدام الحاويات العابرة (Testcontainers):** الاعتماد على محركات قواعد بيانات حقيقية (PostgreSQL / Redis) بدلاً من `go-sqlmock`.
- [ ] **إدارة الحالة النظيفة:** تفريغ الجداول (Truncate) أو التراجع بالمعاملات (Rollback) بين كل اختبار تكاملي.

---

## 5. تكوين الفحص الصارم في `golangci-lint`

تأكد من تفعيل هذه المحللات الخاصة بالاختبار داخل ملف `.golangci.yml`:

```yaml
linters:
  enable:
    - thelper      # يرصد نسيان وضع t.Helper() في دوال المساعدة
    - tparallel    # يكتشف أخطاء نطاق المتغيرات والموازاة
    - paralleltest # ينبه للاختبارات التي تفتقد لـ t.Parallel()
    - testifylint  # يصحح استخدام مكتبة testify ويرتب got قبل want
    - wastedassign # يكشف المتغيرات المهدرة
```

---

## 6. أوامر الـ Makefile المعيارية للـ CI/CD

```makefile
.PHONY: test test-race test-integration test-bench test-stress

# اختبارات الوحدة السريعة مع كاشف السباق
test:
 go test -race -v -timeout=60s ./...

# اختبارات التكامل بالحاويات
test-integration:
 go test -race -v -tags=integration -timeout=10m ./...

# اختبارات الأداء وتخصيص الذاكرة
test-bench:
 go test -run=^$$ -bench=. -benchmem ./...

# اختبار الإجهاد التكراري لرصد أخطاء التزامن المتقطعة
test-stress:
 go test -race -count=50 ./internal/...
```
