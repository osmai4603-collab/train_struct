# مصفوفة الأنماط المضادة الشائعة في اختبارات Go (`Anti-Patterns Matrix`)

توثق هذه المصفوفة أبرز 10 أخطاء هندسية شائعة يقع فيها مطورو Go في اختبارات المشاريع الكبيرة، مع بيان الأثر السلبي، ومثال كود سيء، والبديل القياسي المعتمد عالمياً.

---

| # | النمط المضاد (Anti-Pattern) | لماذا يُعتبر خطأً جسيماً؟ | مثال كود سيء (Bad Code) | البديل القياسي الموصى به (Good Code) |
| :- | :--- | :--- | :--- | :--- |
| **1** | استخدام `time.Sleep` لانتظار العمليات المتزامنة | يسبب اختبارات متقلبة (Flaky Tests) ويبطئ الـ CI بعشرات الثواني غير الضرورية. | `go worker.Run()`<br>`time.Sleep(2*time.Second)`<br>`checkStatus()` | استخدام `sync.WaitGroup`، أو قنوات المزامنة، أو `testing/synctest` في Go 1.24+. |
| **2** | نسيان `t.Parallel()` في الاختبارات الآمنة | إهدار إمكانيات عتاد الـ CI متعدد الأنوية وإطالة زمن تنفيذ حزمة الاختبارات بالكامل. | `func TestA(t *testing.T) { ... }`<br>(بدون تفعيل الموازاة) | إضافة `t.Parallel()` في الدالة الرئيسية وكل `t.Run` فرعي. |
| **3** | استخدام `defer` للتنظيف داخل `t.Run` | الـ `defer` يرتبط بالدالة الحاضنة ولا ينفذ عند انتهاء الاختبار الفرعي، مما يعطل `t.Parallel()`. | `t.Run("sub", func(t *testing.T) {`<br>`db := open()`<br>`defer db.Close()`<br>`})` | استبداله بـ `t.Cleanup(func() { db.Close() })`. |
| **4** | الاعتماد على `go-sqlmock` لاستعلامات SQL المعقدة | يختبر تطابق النص فقط ويتجاهل الأخطاء التركيبية، والمفاتيح الأجنبية، ومشاكل الـ Transactions. | `mock.ExpectQuery("SELECT").`<br>`WillReturnRows(rows)` | استخدام `testcontainers-go` مع حاوية Postgres مؤقتة حقيقية. |
| **5** | توليد Mocks ضخمة لكل دوال النظام | يجعل الاختبارات هشة وتنهار عند أي Refactoring داخلي دون تغيير السلوك العام. | استدعاء `mockery` لكل مستودع وتعريف شجرة توقعات هائلة. | كتابة In-Memory Fake بسيط ومحمي بقفل `sync.RWMutex`. |
| **6** | إطلاق `t.Fatal` داخل دوال المساعدة دون `t.Helper()` | يشير سجل الخطأ إلى رقم السطر داخل الدالة المساعدة بدلاً من سطر الاختبار المستدعي. | `func check(t *testing.T, err error) {`<br>`if err != nil { t.Fatal(err) }`<br>`}` | إضافة `t.Helper()` كأول تعليمة في دالة المساعدة. |
| **7** | تشغيل الاختبارات في الـ CI بدون `-race` | تسلل سباقات بيانات كارثية وتضارب الذاكرة الصامت للإنتاج. | `go test ./...` | فرض `go test -race -count=1 ./...` كفحص إلزامي في الـ CI. |
| **8** | تعديل المتغيرات البيئية عبر `os.Setenv` يدوياً | تلوث بيئة العملية وتأثير جانبي يغير سلوك الاختبارات المتوازية اللاحقة. | `os.Setenv("PORT", "8080")`<br>`defer os.Unsetenv("PORT")` | استخدام `t.Setenv("PORT", "8080")` التي تعيد البيئة تلقائياً. |
| **9** | نسيان `b.ResetTimer()` في الـ Benchmark | احتساب وقت تهيئة الموارد وقواعد البيانات ضمن زمن المعالجة المقاس. | `func BenchmarkX(b *testing.B) {`<br>`setupHeavyDB()`<br>`for i := 0; i < b.N; i++ { ... }`<br>`}` | استدعاء `b.ResetTimer()` مباشرة بعد انتهاء التجهيز وقبل حلقة القياس. |
| **10** | حشو جداول الاختبار بمنطق شرطي متشعب | يحول جدول الاختبار إلى كود معقد يصعب فهمه وتتبعه بدلاً من كونه بيانات توصيفية نقية. | إضافة حقول دوال مجهولة داخل `struct` الجدول وشروط `if tc.customFn != nil`. | فصل الحالات المعقدة إلى دوال `Test...` منفصلة ذات سيناريو واضح. |
