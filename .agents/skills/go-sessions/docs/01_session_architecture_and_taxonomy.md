# 01. المعمارية العامة وتصنيف الجلسات (`Session Architecture & Taxonomy`)

تُعد إدارة الجلسات (Session Management) ركيزة الحفاظ على حالة المصادقة (Stateful Authentication) في تطبيقات الويب. يحدد هذا الدليل المعايير الهندسية للمفاضلة بين الأنواع المختلفة للجلسات في المشاريع الضخمة المكتوبة بلغة Go.

---

## 1. المفاضلة بين الجلسات ورموز JWT

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        مصفوفة المفاضلة المعمارية                       │
├──────────────────────┬────────────────────────┬────────────────────────┤
│ المعيار الهندسي      │ الجلسات من جانب الخادم │ رموز JWT عديمة الحالة  │
│                      │ (Server-Side Sessions) │ (Stateless JWT)        │
├──────────────────────┼────────────────────────┼────────────────────────┤
│ الإلغاء الفوري       │ فوري وقاطع (O(1)) عبر  │ مستحيل بدون قائمة سوداء│
│ (Instant Revocation) │ حذف المفتاح من التخزين │ مركزية (تحولها لـState)│
├──────────────────────┼────────────────────────┼────────────────────────┤
│ حظر التزامن والأجهزة │ تتبع فوري وتحديد دقيق  │ معقد ويتطلب            │
│ (Concurrent Limits)  │ لعدد الأجهزة المتصلة   │ تتبع حالة إضافية       │
├──────────────────────┼────────────────────────┼────────────────────────┤
│ حجم الحمولة الشبكية  │ ثابت وصغير جداً        │ كبير (500B - 2KB+) في  │
│ (Bandwidth Overhead) │ (~64-128 Bytes كـ ID)  │ كل طلب HTTP            │
├──────────────────────┼────────────────────────┼────────────────────────┤
│ تعديل الصلاحيات      │ ينعكس في الطلب التالي  │ ينتظر انتهاء صلاحية    │
│ (Role Mutation)      │ مباشرة من الخادم       │ الرمز الحالي (`exp`)   │
├──────────────────────┼────────────────────────┼────────────────────────┤
│ حساسية البيانات      │ البيانات محفوظة خلف    │ البيانات مشفرة Base64  │
│ (Data Exposure)      │ الجدار الناري للخادم   │ ومكشوفة لأي وسيط يقرأها│
├──────────────────────┼────────────────────────┼────────────────────────┤
│ استهلاك الذاكرة      │ يتطلب مخزناً مركزياً   │ لا يستهلك ذاكرة خادم   │
│ (Storage Overhead)   │ (Redis أو Database)    │ (الذاكرة في التوقيع)   │
└──────────────────────┴────────────────────────┴────────────────────────┘
```

## 2. النمط الهجين الموصى به: Backend For Frontend (BFF)

في الأنظمة الموزعة والميكروسيرفيسز، يُحظر كشف رموز الـ JWT مباشرة للمتصفح. بدلاً من ذلك، نستخدم معمارية BFF:

```text
[ Browser Client ]
       │
       │ HTTPS + __Host-Session-ID (Cookie)
       ▼
┌─────────────────────────────────────────────────────────────┐
│              API Gateway / Backend-For-Frontend (BFF)       │
│                                                             │
│ 1. قراءة كوكي الجلسة والتحقق من صلاحيتها في Redis           │
│ 2. استخراج بيانات المستخدم وأدواره                          │
│ 3. سك رمز JWT داخلي قصير الأجل (mTLS + JWS)                  │
└───────────────────────┬─────────────────────────────────────┘
                        │
       ┌────────────────┴────────────────┐
       │ Internal mTLS + Ephemeral JWT   │
       ▼                                 ▼
┌──────────────┐                  ┌──────────────┐
│ Order Service│                  │Payment Svc   │
└──────────────┘                  └──────────────┘
```

## 3. تصنيف وسائط التخزين (Storage Tiers)

### 3.1 الجلسات في ذاكرة العملية (In-Memory)

- **الآلية:** تخزين الجلسات داخل خريطة (`sync.Map` أو `map[string]*Session` مع `sync.RWMutex`).
- **المزايا:** زمن وصول فائق الصغر في الـ Heap.
- **العيوب:** فقدان تام للبيانات عند إعادة التشغيل، واستحالة التوسع الأفقي (Horizontal Scaling).
- **الاستخدام:** اختبارات الوحدة المحلية (Unit Tests) فقط.

### 3.2 الجلسات المخزنة لدى العميل (Client-Side Encrypted Cookie Store)

- **الآلية:** تشفير بيانات الجلسة بالكامل وتوقيعها عبر خوارزميات AEAD (مثل AES-GCM أو ChaCha20-Poly1305)، وإرسالها بالكامل داخل قيمة الـ Cookie (مثل `gorilla/securecookie`).
- **المزايا:** لا تتطلب قاعدة بيانات خلفية، تتيح التوسع الأفقي دون تخزين مركزي.
- **العيوب:** سقف 4096 بايت، صعوبة الإلغاء الفوري، وهجمات إعادة التشغيل (Replay Attacks).
- **الاستخدام:** البيانات غير الحساسة، وسلات التسوق المؤقتة للزوار غير المسجلين.

### 3.3 الجلسات الموزعة في الذاكرة (Distributed Key-Value: Redis)

- **الآلية:** تخزين حالة الجلسات في عنقود Redis مركزي مع معرّف عشوائي يُعطى للعميل.
- **المزايا:**
  - زمن استجابة منخفض جداً (< 1-2ms).
  - انتهاء صلاحية تلقائي بالكامل عبر TTL.
  - دعم الذرية عبر أوامر Redis المتعددة والـ Lua Scripts.
- **الاستخدام:** **المعيار الصناعي الأول عالمياً** لخدمات الويب عالية التردد.

### 3.4 الجلسات في قواعد البيانات العلائقية (Relational DB: PostgreSQL)

- **الآلية:** جدول مخصص للجلسات يحوي حقل `jsonb` للبيانات ومعرف الجلسة المجزأ وفهرس على تاريخ الانتهاء.
- **المزايا:** تكامل مع المعاملات البنكية (ACID)، وإمكانية الاحتفاظ بسجلات التدقيق الجنائي (Audit Logs).
- **العيوب:** استهلاك دورات I/O مرتفعة مقارنة بـ Redis.
- **الاستخدام:** المنصات المؤسسية والمالية التي تتطلب بقاء الجلسات لفترات طويلة مع قيود تدقيق صارمة.

## 4. تصنيف نطاقات الاستهلاك (Consumption Scopes)

1. **جلسات متصفحات الويب (Web Sessions):** تعتمد على الكوكيز المؤمنة ببادئة `__Host-` وخاصيتي `HttpOnly` و `SameSite`.
2. **جلسات تطبيقات الهاتف المحمول (Mobile API Sessions):** تعتمد على تمرير معرّف الجلسة كرمز في الترويسة `Authorization: Bearer <session_token>`.
3. **الجلسات الممتدة ("Remember Me" Sessions):** جلسات طويلة الأمد مع شروط حماية إضافية وإلغاء صلاحية الوصول للعمليات الحساسة.
4. **جلسات العمليات الحساسة (Sudo / Step-Up Sessions):** حالة مؤقتة (5-10 دقائق) تمنح للمستخدم بعد تأكيد كلمة المرور أو رمز 2FA لإتمام عمليات حساسة (مثل تغيير البريد أو تحويل الأموال).
