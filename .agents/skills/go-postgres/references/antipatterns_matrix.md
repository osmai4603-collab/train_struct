# مصفوفة الأنماط المضادة لقاعدة بيانات PostgreSQL في Go

تحدد هذه المصفوفة أخطر الأنماط البرمجية المضادة (Anti-Patterns) الشائعة عند التعامل مع PostgreSQL في Go، وعواقبها التشغيلية، والبديل القياسي المعتمد في بنيتنا التحتية:

| النمط المضاد (Anti-Pattern) | العواقب والآثار السلبية | النمط الصحيح المعتمد في `internal/infrastructure/postgres` |
|:---|:---|:---|
| **استخدام متغير مجمع عام (`var DB *pgxpool.Pool`)** | فقدان إمكانية العزل في الاختبارات، صعوبة التتبع، وسباقات تزامن غير مراقبة. | **الحقن الصريح للاعتماديات (Explicit Dependency Injection)**: تمرير `*pgxpool.Pool` أو `DBTX` لمنشئات الخدمات والمستودعات. |
| **فتح اتصال جديد لكل طلب HTTP** | انهيار خادم PostgreSQL خلال ثوانٍ بسبب استهلاك الذاكرة وتكلفة مصافحة TCP/TLS العالية. | **مجمع اتصالات موحد دائم (`pgxpool.Pool`)** يدوم طوال عمر التطبيق ويعاد استخدامه. |
| **تسريب `pgconn.PgError` أو SQLSTATE إلى الـ Handlers** | اختراق أمني لكشف تفاصيل الجداول والأعمدة، وارتباط وثيق يكسر المعمارية النظيفة. | **عزل نطاق الفشل عبر `postgres.TranslateError`** فور انتهاء الاستعلام في طبقة المستودع. |
| **إدارة المعاملات يدوياً بدون `defer Rollback`** | ترك أقفال الجداول (Locks) محجوزة وتسريب الاتصالات عند حدوث `panic` أو خطأ مبكر. | **استخدام `postgres.ExecTx`** التي تضمن التراجع التلقائي والتعافي من الانهيارات (`recover`). |
| **إعادة المحاولة بدون تشويش (Retry without Jitter)** | ظاهرة تجمهر الاتصالات (**Thundering Herd**) التي تصيب الخادم بالشلل التام لحظة التعافي. | **استخدام `postgres.WithRetry`** التي تطبق **Exponential Backoff مع Full Jitter**. |
| **إعادة المحاولة لجميع الأخطاء عشوائياً** | إعادة محاولة استعلامات منتهكة للفرادة (`23505`) أو بيانات غير صالحة مما يضيع الموارد دون جدوى. | **حصر إعادة المحاولة بالأخطاء العابرة فقط (`IsTransient`)** مثل `40001` (Serialization) و `40P01` (Deadlock). |
| **تخصيص `MaxConns` ضخم لكل حاوية (مثل 100+)** | خنق معالج PostgreSQL بسبب التبديل المفرط للسياق (Context Switching) ونفاد الذاكرة. | **حساب السعة بالمعادلة الذهبية** وتقييد الحاويات بـ `MaxConns` مدروس (مثل 10-25). |
| **استخدام `fmt.Sprintf` لبناء استعلامات SQL** | ثغرات الحقن القاتلة (**SQL Injection Vulnerabilities**). | **استخدام المعلمات الموضعية المربوطة دائماً (`$1, $2, ...`)** أو الاستعانة بمولدات مثل `sqlc`. |
| **تجاهل فحص خطأ `rows.Err()` بعد حلقة القراءة** | فقدان صامت لسجلات البيانات عند انقطاع الشبكة في منتصف بث النتائج. | **فحص `rows.Err()` دائماً** أو استخدام دوال الفحص المجمعة `pgx.CollectRows`. |
| **تشغيل عمليات ترحيل يدوية متفرقة على قواعد الإنتاج** | تباين المخططات (Schema Drift) وفشل الإصدارات عند عدم تزامن الجداول. | **تضمين الترحيلات عبر `go:embed` وتشغيلها آلياً عبر `postgres.RunMigrations`**. |
