# تأمين وحجب الأسرار (Secret Security & Redaction)

تتعامل ملفات الإعدادات مع بيانات حساسة للغاية (كلمات مرور قواعد البيانات، مفاتيح JWT، الرموز السرية لبوابات الدفع، ورموز API). تسريب هذه البيانات في السجلات أو لوحات المراقبة يمثل ثغرة أمنية كارثية.

---

## 1. نمط الحجب في السجلات (The Redacted Pattern)

يجب ألا يتم تسجيل هيكل الإعدادات في سجلات التطبيق (`slog.Info("config loaded", "config", cfg)`) دون تمريره عبر دالة حجب متخصصة:

### الدالة `cfg.Redacted()`

تقوم بعمل نسخة سطحية (Shallow Copy) وتستبدل كافة البيانات السرية بالقيمة المحجوبة `***`:

- `Database.Password` $\longrightarrow$ `"***"`
- `Auth.JWTSecret` $\longrightarrow$ `"***"`

### حجب روابط الاتصال (Connection URL Masking)

عند استخدام روابط اتصال مثل:
`postgres://train_user:SuperSecretPassword123@db.internal:5432/train_db`
يجب أن تقوم دالة الفلترة `MaskURL` بتحليل الرابط وإخفاء كلمة المرور وفك تشفير النجوم لتظهر صراحة:
`postgres://train_user:***@db.internal:5432/train_db`

---

## 2. أذونات ملفات التكوين (Strict File Permissions)

عند قيام الخدمة بقراءة أو كتابة ملف تكوين يحتوي على كلمات مرور أو مفاتيح، يجب فرض أذونات نظام الملفات الصارمة:

```go
const SecureConfigPerm = os.FileMode(0o600) // Read & Write for owner ONLY (-rw-------)
```

- **لماذا `0600`؟**: في بيئات الاستضافة المشتركة أو الخوادم متعددة المستخدمين، يمنع هذا التصريح أي مستخدم آخر على نظام التشغيل من قراءة محتويات ملف التكوين.

---

## 3. تجنب تخزين كلمات المرور كنصوص صريحة (Password Hashing)

إذا كانت الإعدادات تتضمن كلمة مرور لحساب إداري داخلي (Admin Password)، يجب ألا تُخزن كنص صريح (Plaintext):

- استخدام خوارزميات التجزئة القوية مع إضافة Salt عشوائي مثل `PBKDF2-SHA512` (بعدد دورات لا يقل عن 600,000 دورة) أو `Argon2id` أو `bcrypt`.
- تخزين الـ Hash فقط في الإعدادات، واستخدام المقارنة ذات الزمن الثابت (`subtle.ConstantTimeCompare`) لمنع هجمات التوقيت (Timing Attacks) أثناء التحقق من كلمة المرور.
