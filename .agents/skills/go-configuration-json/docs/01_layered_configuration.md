# معمارية التكوين متعدد الطبقات (Layered Configuration Architecture)

في الخدمات السحابية والأنظمة المؤسسية، لا يمكن الاعتماد على مصدر واحد للإعدادات. يحتاج المطور إلى قيم افتراضية سريعة أثناء التطوير، ويحتاج مهندس العمليات في بيئة الاختبار إلى ملف تكوين ثابت (JSON)، بينما تتطلب بيئات الحاويات (Docker & Kubernetes) تمرير الإعدادات عبر المتغيرات البيئية (Environment Variables).

---

## هرمية الأسبقية (The Priority Hierarchy)

تعتمد المهارة ترتيب أسبقية صارم (من الأضعف إلى الأقوى):

$$\text{1. Defaults} \longrightarrow \text{2. Config File} \longrightarrow \text{3. Environment} \longrightarrow \text{4. CLI Flags} \longrightarrow \text{5. Runtime Overrides}$$

```text
┌───────────────────────────────────────────────────────────┐
│ 5. Runtime Overrides (برمجياً أثناء الاختبارات)           │  ▲ الأقوى
├───────────────────────────────────────────────────────────┤  │
│ 4. CLI Flags (--port 8080)                                │  │
├───────────────────────────────────────────────────────────┤  │
│ 3. Environment Variables (APP_PORT, PORT, PGHOST)         │  │
├───────────────────────────────────────────────────────────┤  │
│ 2. Config File (config/config.json)                        │  │
├───────────────────────────────────────────────────────────┤  │
│ 1. Defaults (القيم الافتراضية الصلبة في الكود)            │  ▼ الأضعف
└───────────────────────────────────────────────────────────┘
```

---

## قواعد الدمج (Merging Rules)

1. **البداية بالقيم الافتراضية (Defaults First)**:
   يتم البدء دائماً بتركيبة إعدادات مكتملة ومملوءة بقيم آمنة (`DefaultConfiguration()`).
2. **الدمج الانتقائي من الملف (Sparse File Unmarshal)**:
   عند قراءة ملف JSON، يتم تفكيكه فوق (Merge into) تركيبة الـ Defaults. المفاتيح الموجودة في الملف فقط هي التي تعيد كتابة القيمة الافتراضية، بينما تحتفظ المفاتيح الغائبة بقيمتها الافتراضية السليمة.
3. **أسبقية المتغيرات البيئية (Env Overrides)**:
   تفحص مكتبة التحميل المتغيرات البيئية؛ فإذا وُجد متغير بيئي، فإنه يتفوق على ما ورد في الملف والقيم الافتراضية.
4. **دعم الأسماء البديلة (Aliases)**:
   في بيئات السحاب، يُستخدم مثلاً `DATABASE_URL` كمعيار شائع، بينما تدعم بيئات PostgreSQL أسماء قياسية مثل `PGHOST` و `PGPORT` و `PGUSER`. يدعم محرك الإعدادات المفتاح الأساسي والأسماء البديلة بترتيب واضح.
5. **أسرار الملفات المحقونة (File-Based Secrets: *_FILE)**:
   في بيئات الحاويات و Kubernetes، يتم دعم قراءة كلمات المرور والرموز السرية مباشرة من مسارات الملفات المقيدة (`DB_PASSWORD_FILE`, `JWT_SECRET_FILE`).
6. **رايات سطر الأوامر (CLI Flags)**:
   إذا تم تمرير علم صريح للمشغل في سطر الأوامر (مثل `--port 9000`)، فإن له الكلمة العليا فوق البيئة والملف.
7. **التجاوزات البرمجية (Runtime Overrides)**:
   دوال التعديل البرمجية اللحظية للمسارات الاختبارية وحقن الموانئ العشوائية (Ephemeral Ports).
