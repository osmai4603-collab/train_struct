# قائمة مراجعة الجاهزية للإنتاج لـ Go JWT (Production Checklist)

استخدم هذه القائمة أثناء مراجعة الكود (Code Review) وقبل دمج أو نشر أي خدمة تعتمد على الـ JWT في بيئات الإنتاج:

---

## 1. التشفير والخوارزميات (Cryptography & Algorithms)
- [ ] **حظر `none`:** تم التأكد من رفض الرموز ذات التوقيع `none` بصورة قطعية ولا يمكن قبولها تحت أي ظرف.
- [ ] **قائمة الخوارزميات البيضاء:** تم تفعيل `jwt.WithValidMethods` وحصرها في الخوارزمية المقررة (مثل `EdDSA` أو `PS256`) لمنع هجمات الخلط التشفيري (Key Confusion).
- [ ] **إنتروبيا وأطوال المفاتيح:** 
  - في حال استخدام التوقيع المتناظر (HMAC): المفتاح يمتلك إنتروبيا عشوائية لا تقل عن 256 بت (`crypto/rand`).
  - في حال استخدام RSA: طول المفتاح لا يقل عن 2048 بت، مع تفضيل `PS256` على `RS256`.
  - في حال استخدام المنحنيات الإهليلجية: اعتماد `Ed25519` كخيار أول، أو `ES256` مع تطبيق التوقيع الحتمي RFC 6979.
- [ ] **المقارنة الثابتة زمنياً:** يتم فحص الرموز الأحادية أو أسرار التوقيع عبر `crypto/subtle.ConstantTimeCompare`.

---

## 2. إدارة المفاتيح ومجموعات JWKS (Key Management)
- [ ] **كاش محلي ذكي:** خوادم الموارد لا تستدعي خادم الـ JWKS مع كل طلب وارد؛ يوجد كاش محلي في الذاكرة مع تحديث دوري بالخلفية.
- [ ] **مقاومة هجمات الإغراق (Anti-Throttling):** عند طلب `kid` غير موجود بالكاش، يتم تأخير وإعادة محاولة الجلب بنمط Rate-Limited Debounce لمنع إسقاط خادم المفاتيح بهجمات الـ DDoS.
- [ ] **التدوير الخالي من التوقف (Zero-Downtime):** خادم الإصدار ومكتبة الفحص يدعمان فترات التداخل الزمني (Grace Period) بين المفتاح القديم والمفتاح الجديد.
- [ ] **تحصين الـ `kid`:** يتم فحص معرّف المفتاح ضد التعبيرات النمطية المقفلة (`^[a-zA-Z0-9_-]+$`) ولا يتم استخدامه مباشرة كمسار ملف أو استعلام قاعدة بيانات.
- [ ] **حظر روابط الرأس الخارجية:** تم تجاهل ترويسات `jku` و `x5u` ورفض تحميل أي مفاتيح من روابط يحددها العميل.

---

## 3. الصلاحيات ودورة حياة الرمز (Lifecycle & Claims)
- [ ] **عمر رمز الوصول (Access Token):** مضبوط بين 5 إلى 15 دقيقة كحد أقصى للحد من أثر أي سرقة محتملة.
- [ ] **تدوير رموز التحديث (RTR):** تفعيل كاشف تكرار الاستخدام (Reuse Detection) وإلغاء عائلة الرموز بالكامل فور محاولة استخدام رمز تحديث مستهلك.
- [ ] **التحقق الإلزامي من الادعاءات:** فحص `exp` (تاريخ الانتهاء)، `iss` (المصدر الموثوق)، `aud` (اسم الخدمة الحالية تحديداً)، و `nbf`.
- [ ] **هامش تفاوت التوقيت (Clock Skew):** تحديد مهلة التفاوت بين ساعات الخوادم بما لا يتجاوز دقيقة واحدة (`jwt.WithLeeway(1 * time.Minute)`).
- [ ] **آلية الإلغاء الفوري:** توفير مسار لإلغاء الجلسات عند تسجيل الخروج (Redis Blacklist مع TTL لـ `jti`، أو User Token Epoch `iat >= user.token_valid_after`).

---

## 4. النقل والتخزين وأمان الواجهات (Transport & Storage)
- [ ] **HTTPS الإلزامي:** فرض التشفير التام أثناء النقل لكافة مسارات الرموز ورفض اتصالات HTTP غير المشفرة.
- [ ] **ملفات الارتباط الآمنة في المتصفح:** تخزين رموز التحديث داخل كوكيز تحمل البادئة **`__Host-`** وخاصية `HttpOnly` و `Secure` و `SameSite=Strict`.
- [ ] **الترويسة القياسية:** استخدام `Authorization: Bearer <token>` في تعاملات واجهات برمجة التطبيقات وتطبيقات الهاتف.
- [ ] **الخلو من البيانات الحساسة:** خلو حمولة الـ JWS تماماً من أي بيانات شخصية (PII) أو أسرار داخلية، أو استخدام التشفير الكامل **JWE**.

---

## 5. الأداء والمراقبة والتطبيق في Go (Observability & Go Patterns)
- [ ] **مفتاح سياق غير مصدّر:** تخزين ادعاءات المستخدم داخل `context.Context` عبر نوع مخصص غير مصدّر `type contextKey struct{}`.
- [ ] **تعتيم السجلات:** تغليف الرموز بنوع يطبق `slog.LogValuer` لمنع ظهور الرموز أو طباعتها في السجلات الموزعة.
- [ ] **عزل ومعالجة الأخطاء:** استخدام `errors.Is` مع الأخطاء القياسية لحزمة الـ JWT وترجمتها إلى رموز استجابة HTTP المناسبة (401 للانتهاء وتلف التوقيع، 403 للصلاحيات).
- [ ] **كفاءة الذاكرة:** خلو مسار وسيط الـ HTTP من التخصيصات العشوائية للذاكرة وتفادي الانعكاس (`reflect`) غير الضروري.
