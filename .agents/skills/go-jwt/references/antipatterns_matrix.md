# مصفوفة الأنماط المضادة وتصحيحها في Go JWT (Anti-Patterns Matrix)

| # | النمط المضاد (Anti-Pattern) | المخاطر المترتبة في الإنتاج | الكود الخاطئ | الكود المعياري المعتمد |
|:---|:---|:---|:---|:---|
| 1 | **استخدام `ParseUnverified` لاتخاذ قرارات أمنية** | قراءة بيانات الرمز دون التحقق من التوقيع، مما يتيح لأي مهاجم تزوير دور Admin وتجاوز النظام بالكامل. | `token, _ := parser.ParseUnverified(tokenStr, &claims)`<br>`if claims.IsAdmin { grant() }` | استخدام `jwt.Parse` أو `jwt.ParseWithClaims` مع التحقق الكامل من التوقيع والمصدر والصلاحية. |
| 2 | **إهمال قائمة الخوارزميات المسموحة (`WithValidMethods`)** | هجمات الخلط التشفيري (Key Confusion): خداع الخادم للتحقق من مفتاح RSA العام باستخدام سر HMAC. | `jwt.Parse(tokenStr, keyFunc)` | `jwt.Parse(tokenStr, keyFunc, jwt.WithValidMethods([]string{"PS256", "EdDSA"}))` |
| 3 | **السماح بـ `alg: none` في خادم الإنتاج** | تزوير أي رمز دون توقيع بمجرد إرسال الرأس `"alg": "none"` وتفريغ قسم التوقيع. | قبول الرموز بدون فحص التوقيع أو تعطيل فحص الخوارزمية. | الرفض التام لـ `none`، وإلزام وجود توقيع صالح و `jwt.WithValidMethods`. |
| 4 | **رموز وصول طويلة الأجل (أيام أو أسابيع)** | في حال سرقة الرمز من المتصفح أو الشبكة، يستطيع المهاجم الوصول للنظام طوال هذه المدة دون وسيلة سهلة لإبطاله. | `exp: time.Now().Add(30 * 24 * time.Hour)` لرمز الـ Access Token. | قصر عمر Access Token على 5-15 دقيقة، واستخدام Refresh Token مع التدوير الإلزامي (RTR). |
| 5 | **تخزين الرموز في `localStorage` بالمتصفح** | أي ثغرة XSS أو سكريبت خبيث في حزم npm يستطيع قراءة الرمز وإرساله لخادم خارجي فوراً. | `localStorage.setItem('access_token', token)` | تخزين الرموز في ملفات ارتباط `HttpOnly`، `Secure`، `SameSite=Strict` مع بادئة `__Host-`. |
| 6 | **وضع أسرار النظام والبيانات الحساسة في JWS** | الـ JWS ليس تشفيراً بل ترميز Base64URL مكشوف لأي وسيط يقرأ الـ Token في الشبكة أو المتصفح. | `claims["ssn"] = "123-45-6789"`<br>`claims["db_password"] = "secret"` | إما وضع معرّف مشفر عشوائي (Opaque ID) أو استخدام التشفير الكامل **JWE (RFC 7516)**. |
| 7 | **الاتصال المتزامن بخادم JWKS مع كل طلب HTTP** | مضاعفة زمن الاستجابة، استنزاف شبكة خادم المصادقة، وجعله نقطة انهيار مفردة (SPOF). | `func Validate(...) { resp, _ := http.Get("https://auth/.well-known/jwks.json") }` | استخدام كاش محلي في الذاكرة (Thread-safe In-Memory Cache) مع تحديث دوري في الخلفية. |
| 8 | **استخدام نصوص (`string`) كمفاتيح في `context.Context`** | تصادم المفاتيح بين الحزم البرمجية المختلفة وتجاوز بيانات المستخدم بالخطأ. | `ctx = context.WithValue(ctx, "user", claims)` | استخدام نوع هيكل فارغ غير مصدّر: `type userKey struct{}` |
| 9 | **مقارنة الرموز باستخدام `==` العادية** | تعريض النظام لهجمات قياس التوقيت (Timing Attacks) واستنتاج الرموز بايت تلو الآخر. | `if clientToken == storedToken { ... }` | استخدام المقارنة الثابتة زمنياً:<br>`subtle.ConstantTimeCompare([]byte(a), []byte(b)) == 1` |
| 10 | **إهمال فحص حقل الجمهور `aud` (Audience)** | إعادة استخدام رمز صادر لنظام متدني الأمان لاختراق واجهات نظام مالي أو إداري حساس. | إهمال التحقق من `aud` في قواعد الـ Parser. | إلزام مطابقة حقل `aud` مع المعرّف الفريد للخدمة المستقبلة: `jwt.WithAudience("billing-service")`. |
| 11 | **طباعة كائن الرمز أو الـ Claims في السجلات (`slog`)** | تسريب مفاتيح الدخول للجلسات إلى شاشات ومخازن السجلات المركزية (Datadog/Splunk). | `slog.Info("authenticated", "token", tokenStr)` | تطبيق واجهة `slog.LogValuer` لتعتيم الرمز تلقائياً واستبداله بـ `[REDACTED]`. |
| 12 | **الثقة بـ `kid` أو `jku` دون فحص أمني** | هجمات حقن المسارات (Path Traversal مثل `kid: ../../../dev/null`) أو توجيه الخادم لتحميل مفاتيح مهاجم. | `keyPath := "/keys/" + token.Header["kid"]`<br>`os.ReadFile(keyPath)` | فحص `kid` بنمط تعبيري صارم (`^[a-zA-Z0-9_-]+$`)، والتحقق منه داخل خريطة مفاتيح مغلقة مسبقاً. |
