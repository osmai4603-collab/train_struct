# قائمة مراجعة الجاهزية للإنتاج لأنظمة الأخطاء (Production Readiness Checklist)

قبل اعتماد أي كود أو إطلاق خدمة إلى بيئة الإنتاج، يجب التحقق من كافة البنود التالية:

---

## 1. الفلسفة الأساسية وبنية الأخطاء

- [ ] **الأخطاء كقيم:** هل تُعامل كافة الأخطاء كقيم عادية وتُفحص فوراً في نقطة حدوثها (`Fail Fast`)؟
- [ ] **المستهلكون الثلاثة:** هل تم استخدام هيكل `platformerr.Error` لخدمة التطبيق (`Code`)، والمستخدم (`Message`)، والمشغل (`Op`, `Err`)؟
- [ ] **الأكواد المعيارية:** هل تم استخدام الأكواد الرسمية المعتمدة (`NOT_FOUND`, `INVALID`, `CONFLICT`, `INTERNAL`, ...) دون ابتكار أكواد عشوائية؟

## 2. ميكانيكا التغليف والفحص

- [ ] **فحص الهوية:** هل تم استخدام `errors.Is` بدلاً من عامل المقارنة `==` في كافة عمليات التحقق من أخطاء الحارس؟
- [ ] **استخراج الأنواع:** هل تم استخدام `errors.As` بدلاً من الـ Type Assertion اليدوي (`err.(*CustomType)`)؟
- [ ] **التغليف الواعي:** هل تم استخدام `%w` حصراً للأخطاء المقصود كشفها، واستخدام `%v` أو `platformerr.Internal` لإخفاء تفاصيل البنية التحتية؟

## 3. حدود الطبقات وترجمة الأخطاء

- [ ] **طبقة التخزين (Repository):** هل تترجم طبقة التخزين أخطاء SQL والمحركات (مثل `sql.ErrNoRows` أو خطأ التكرار) إلى أخطاء نطاق (`NotFound` أو `Conflict`)؟
- [ ] **طبقة النقل (HTTP Handlers):** هل تُترجم الأخطاء في طبقة النقل بواسطة `platformerr.WriteHTTPError` لمنع تسريب أسماء الجداول أو استعلامات SQL للعميل؟
- [ ] **قاعدة التسجيل أو الإرجاع:** هل تلتزم كافة الدوال بقاعدة "التسجيل أو الإرجاع" (Log OR Return, Never Both) لمنع تكرار السجلات؟

## 4. العمليات المتزامنة والموارد

- [ ] **أخطاء Goroutines:** هل تُدار العمليات المتزامنة بواسطة `errgroup.Group` بدلاً من إطلاق Goroutines تفشل بصمت في الخلفية؟
- [ ] **إغلاق الموارد (defer):** هل يتم التقاط أخطاء دوال `defer file.Close()` ودمجها عبر `errors.Join` في الدوال الحساسة لكتابة وتعديل البيانات؟

## 5. الأمان وسلامة النظام

- [ ] **تنقية الأسرار:** هل تم التأكد من خلو رسائل الأخطاء وسجلات التسجيل من كلمات المرور، رموز JWT، وأرقام البطاقات (PII Redaction)؟
- [ ] **حماية الذعر (Panic Recovery):** هل خادم الويب محمي بـ `Recovery Middleware` لالتقاط أي ذعر غير متوقع وإرجاع رد HTTP 500 آمن دون انهيار الخادم؟
- [ ] **تنسيق Go القياسي:** هل تبدأ كافة رسائل الأخطاء بحروف صغيرة (lowercase) وبدون نقطة في النهاية؟
